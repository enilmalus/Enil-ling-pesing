## 3. 已测入口（防重复、防漏测）

| 入口 | 已测类目（playbook 名） | 已试 payload / 命令（关键字） | 响应特征（状态码 / 长度 / 报错关键字） | 结论 + 封锁判据 | 证据位置 |
|---|---|---|---|---|---|
|  |  |  |  |  |  |

**结论栏填写规则**（与 SKILL.md Phase 3 第 5 条一致）：

- `命中`：写出候选/已确认漏洞编号（进 §4）。
- `封锁`：必须写满四条判据——① 对应 playbook 探测顺序走完；② bypass 矩阵主要分支试过；③ 已归因（非环境/凭据问题）；④ 换过一次**机理不同**的打法仍不成立。
- `未探尽`：缺任一判据时的唯一合法写法（**禁止**直接写"无洞""不可注入"）。
- `未测`：尚未开始的入口（通常由 §2 资产矩阵带出）。**不要**用 `未探尽` 代替 `未测`——前者表示已试过。

> **旧文件迁移**：本表原为「入口 / 测过的类目 / 结论 / 证据位置」四列。迁移方式：在「已测类目」后补两列（已试 payload、响应特征），历史行填 `-`；结论栏按上面规则回填——**没测过的填 `未测`，测过但判据不全的填 `未探尽`**，两者不可混用。
