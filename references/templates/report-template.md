# 渗透测试报告模板

> Phase 5 使用。按此结构输出；`[]` 内为填写说明。

## 执行摘要

- 测试范围：`[域名/IP/系统清单]`
- 授权依据与测试时间：`[合同号或平台项目 / 起止时间]`
- 测试方法：`[黑盒/灰盒，主动/被动，是否包含破坏性测试]`
- 风险统计：`[严重 x / 高 x / 中 x / 低 x / 信息 x]`
- 总体结论：`[一句话结论 + 最高风险项]`

## 漏洞详情

每个 finding 一小节，格式固定：

### `[资产/URL] [漏洞类型] — 一句话描述`（标题 ≤80 字）

- **风险评级**：CVSS 3.1 vector `CVSS:3.1/AV:.../AC:.../...` + 严重度
- **漏洞描述**：成因与影响机制（2-4 句）
- **复现步骤**：
  1. 逐步可执行，附 curl 命令或 HTTP 包
  2. `[请求原文]` / `[响应原文]`
  3. 截图：`[文件名]`
- **影响分析**：业务影响 + 攻击者视角最坏结果
- **修复建议**：
  - 根因修复：`[代码/配置层面的修复]`
  - 缓解措施：`[WAF 规则/限制/监控]`
  - 优先级与工作量估计

## 附录

- 资产清单：`[表]`
- 工具输出节选：`[nmap/nuclei 等]`
- 测试用账号与 header：`[如 X-Bug-Bounty: xxx]`

## 输出纪律

- 每个 finding 必须能由复现步骤独立重建
- 无证据的观察写入"附录·待验证项"，不进漏洞详情
- 修复建议按"根因修复优先于缓解"排序
