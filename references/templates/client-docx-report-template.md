# 客户标准 docx 报告模板（渗透测试交付格式）

> Phase 5 使用。用户的标准交付格式，综合用户两版定稿 docx（2026-09 最终版）提炼。
> 生成工具：`~/Work/Tools/md2clientdocx/md2clientdocx.py`——先按 `report-template.md` 写好 finding markdown，再一键转 docx。
> F 盘产物会被 DLP 透明加密（`%TSD` 头）：WSL 侧无法读写 docx 本体，需要改 DLP 管的文档时生成独立文件让用户在 Word 里粘贴，禁止试图就地编辑。

## 文档结构（严格层级）

```
H1 居中：报告总标题（如 "XX集团多站点渗透测试报告"）
目录页（TOC 域，Word 内按 F9 更新）
H1：注意事项（测试账号/Token 来源/前置声明，无则写"无"）
H1：一、<资产>（系统名）                  ← 每个资产一组，汉字序号
  H3：1.1 <漏洞类型>：一句话描述           ← 每个漏洞一节
    H4：1.1.1 漏洞描述
    H4：1.1.2 修复建议
    H4：1.1.3 验证过程
```

- 编号规则：H3 = `资产序号.漏洞序号`（1.1, 1.2, ... 2.1 ...）；H4 = `1.1.1` 三段固定顺序
- H3 标题格式：`漏洞类型：描述`（如 `垂直越权：任意用户密码重置`），**风险等级直接写在标题尾部括号里**（如 `...任意用户密码重置（高危）`）——最终版全文 34 条均带等级标注，不是可选项
- **不设执行摘要/漏洞×资产矩阵/附录等章节**——最终版文档正文只有「注意事项 + 资产组」两级，矩阵和附录内容并入「注意事项」的 bullet（范围/分组/风险统计/总体结论/纪律，一段 bullet 打平）

## 风险统计表（最终版新增必备元素）

多站点报告需附「各站点漏洞数量统计」表（行=各资产组、列=高危/中危/低危/合计、末行总计）。用户已认可的标准形态：

| 站点 | 高危 | 中危 | 低危 | 合计 |
|---|---|---|---|---|
| 一、<资产> | 1 | 3 | 2 | 6 |
| ... | | | | |
| **合计** | **13** | **15** | **6** | **34** |

生成方式：``references/templates/gen_stats_table.py``（python-docx 脚本，样式 Table Grid + 居中 + 微软雅黑，末附评级口径备注）。因主报告被 DLP 加密，此表生成独立 docx 由用户粘贴进主文档。

**评级口径**（无 CVSS 时按影响定级，写进表格备注）：
- 高危：任意密码重置 / 管理员接管 / 批量 PII 泄露 / 任意文件读取配置密码 / 匿名写存储（投毒/篡改）/ 前端私钥与加密协议全破
- 中危：信息泄露、越权读取（非批量 PII）、短信轰炸、无验证码爆破前提、未授权业务数据读取
- 低危：用户枚举、点击劫持、纯接口结构泄露

## 三段式小节内容约定

### 漏洞描述
- 1-3 句成因 + 实测要点（**实测必须写**："实测 N 次""已验证下载他企文件"等），实测内容用 bullet 列表
- 接口名/参数值/凭据用行内代码样式（Courier New + F1F5F9 底纹）

### 修复建议
- 编号列表（1. 2. 3. ...），根因修复在前，缓解/审计在后
- 末条通常是审计告警或回归测试类建议
- 最终版实际用法：三段顺序允许复现步骤在描述后（`1.1.2复现步骤`），不必强制「验证过程」措辞——`漏洞描述 / 复现步骤（或验证过程）/ 修复建议` 三段名均可，**顺序固定为 描述→复现→修复**

### 复现步骤 / 验证过程
- 每个操作一个**加粗「步骤 N：<动作>」**小标题（最终版也有直接用裸 curl 块不带步骤号的，均可接受，一节内保持一致即可）
- 步骤内：`1. 发送：` 编号行 → **黑底白字 Courier 代码块**（完整 HTTP 请求/curl，带 `┌──(kali㉿...)-[~/Work]└─$` 终端提示符的原样保留——用户认这个格式）
- 代码块后：`2. 预期：HTTP 200 {...}` 描述预期响应（含关键响应内容）
- 截图：最终版在验证过程中直接嵌图（md2clientdocx 不生成图片，md 里留步骤文本，图由用户手工补）
- 长响应 JSON 可截断：保留前几个关键字段 + `...`，不必全贴

## md 约定（md2clientdocx.py 的输入格式）

| markdown | docx 结果 |
|---|---|
| `## <资产名>` | H1 `一、<资产名>` |
| `### <漏洞名>` | H3 `1.1 <漏洞名>`（自动剥掉 `N.` 前缀和 `[资产] [类型]` 标签） |
| `#### <小节名>` | H4（漏洞描述/修复建议/验证过程 三选一） |
| ``` 代码块 ```（含列表项内嵌套） | 黑底白字 Courier 代码块 |
| `- bullet` / 嵌套缩进 | bullet 列表 |
| `1. 步骤` | 编号列表 |
| `**加粗**` | 粗体 |
| `` `行内代码` `` | Courier + F1F5F9 底纹 |

## 使用命令

```bash
# 主报告
python3 ~/Work/Tools/md2clientdocx/md2clientdocx.py <report.md> <output.docx> --title "目标 渗透测试报告"
# 统计表（多站点报告）
PYTHONPATH=/home/kali/.local/lib/python3.13/site-packages python3 <skill目录>/references/templates/gen_stats_table.py
```

注意：系统 python3 无 docx 模块不影响 md2clientdocx（纯 zipfile 生成）；python-docx 验证/统计表生成需
`PYTHONPATH=/home/kali/.local/lib/python3.13/site-packages`。
